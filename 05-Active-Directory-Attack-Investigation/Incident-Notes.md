## Initial Observation

The investigation reviewed local account/group activity, authentication failures, privileged logons, and PowerShell Script Block Logging. Controlled failed authentication attempts were generated against the local `Administrator` account to validate detection and correlation.

## Analyst Observations

- The workstation is **WORKGROUP**, so there was no real domain controller or AD domain available for this exercise.
- Event ID 4799 showed local group membership enumeration by PowerShell. In this lab context, this was benign investigation-generated telemetry.
- Three Event ID 4625 records were intentionally generated using an incorrect password for the local `Administrator` account.
- The failed authentication events contained status `0xC000006D` and substatus `0xC000006A`, consistent with an invalid authentication attempt.
- The source for the controlled local authentication attempts was `::1` (IPv6 loopback).
- The reviewed Event ID 4624 records around the test did **not** show a successful Administrator logon. The observed successful events were SYSTEM service logons and should not be incorrectly correlated with the failed Administrator attempts.
- Event ID 4672 records were associated with the SYSTEM account and its normal privileged token. They were not evidence of privilege escalation by DEVSH.
- Event ID 4104 Script Block Logging was reviewed. The observed scripts were Windows troubleshooting/input-method related scripts and the investigation commands themselves. No clear malicious PowerShell activity was identified in the reviewed events.
- No confirmed malicious persistence, credential dumping, or command execution was identified from the reviewed telemetry.

## MITRE ATT&CK Mapping

### T1087 — Account Discovery
**Observed behavior:** Local account/group information was enumerated during the investigation.

**Assessment:** The telemetry is compatible with account/group discovery, but in this lab it was generated by benign investigation activity. It is therefore documented as a technique-relevant observation, not as proof of attacker activity.

### T1059.001 — PowerShell
**Observed behavior:** PowerShell was used for Windows event collection and analysis, and Event ID 4104 captured the commands/scripts.

**Assessment:** PowerShell usage alone is not malicious. The reviewed activity was assessed as benign in this controlled lab.

## Assessment

**Final assessment: 🟢 Benign / No confirmed compromise**

The investigation successfully demonstrated SOC L1 techniques for collecting and correlating Windows authentication, group enumeration, privileged logon, and PowerShell telemetry. The controlled failed authentication sequence generated useful Event ID 4625 evidence, while correlation with Event ID 4624 and 4672 helped avoid false attribution.

No confirmed malicious activity or compromise was identified from the available telemetry.

## Next Steps

- Repeat the workflow in a genuine isolated Active Directory lab when domain infrastructure is available.
- Add domain authentication telemetry such as Kerberos and domain-controller events.
- Correlate endpoint telemetry with a SIEM in a future lab.
- Practice distinguishing benign administrative activity from true attacker discovery and credential attacks.
