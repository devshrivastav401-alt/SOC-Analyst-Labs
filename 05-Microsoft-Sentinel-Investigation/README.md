# 🛡️ Lab 05 — Microsoft Sentinel SIEM Investigation

## 🎯 Objective

Perform a SOC Analyst L1 investigation using Microsoft Sentinel to collect, triage, query, correlate, and document security events from a cloud-based SIEM.

## 🔎 Investigation Focus

- Cloud SIEM alert triage
- KQL log querying
- Windows security event analysis
- Authentication investigation
- Alert/entity analysis
- IOC identification
- Timeline correlation
- Evidence-based incident assessment

## 🧪 Scenario

A cloud SIEM environment contains security telemetry associated with suspicious activity. The analyst uses Microsoft Sentinel and Kusto Query Language (KQL) to identify relevant events, investigate the activity, correlate evidence, and document findings.

> **Lab status:** In Progress

## 🛠️ Tools

- Microsoft Sentinel
- Azure / Log Analytics
- Kusto Query Language (KQL)
- Windows Security Events
- GitHub

## 📋 Investigation Workflow

1. Prepare the Sentinel/Log Analytics environment.
2. Confirm that relevant telemetry is available.
3. Review Sentinel incidents and alerts.
4. Identify relevant entities, timestamps, and event details.
5. Query telemetry using KQL.
6. Correlate related events and build a timeline.
7. Identify relevant indicators.
8. Assess the activity using available evidence.
9. Document findings, limitations, and recommended next steps.
10. Capture screenshots as evidence.

## 📸 Evidence

Screenshots will document:
- Sentinel workspace/dashboard
- Relevant incident or alert
- Alert/entity details
- KQL query and results
- Correlated events/timeline
- Final investigation evidence
